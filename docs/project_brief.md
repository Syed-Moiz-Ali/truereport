# TrueReport — Project Brief (audit baseline)

Status: generated by the flow-gap audit on 2026-11-20. Every line is `confirmed` from code/docs unless marked
`inferred`. This brief is deliberately narrower than the marketing blueprint: it describes what the repository does,
not what the product ambitions say it should do.

## 1. What it is — confirmed

TrueReport is a B2B partner-workshop vehicle-inspection platform. A workshop creates an inspection job for a customer
vehicle, assigns a technician, the technician assesses a pinned checklist (measurements, issue fields, photo/video
evidence, signature), and the workshop reviews/approves the result. An approved job can be published as an
anonymous, token-addressed public report (`/r/{token}`) with an optional PDF download and WhatsApp/SMS/email delivery.

The repository is a monorepo: `client/` is a Dart pub workspace with three product Flutter apps plus a UI gallery;
`server/` is a Spring Boot 4 / Java 25 modular monolith on MySQL 8.4 with Flyway; `infra/` holds Compose, nginx and
monitoring; `docs/` holds phase evidence.

## 2. Who uses it — confirmed unless marked

| Role | App | May do |
|---|---|---|
| Platform Admin | `client/apps/platform_admin_app` | Manage platform workshops and staff, master categories/items/option sets/document types, languages and translation coverage, audit log, config health/releases, overview dashboard. |
| Workshop Admin | `client/apps/workshop_admin_app` | Manage own staff, build templates from master content, create/assign/cancel jobs, review and approve/reject inspections, publish/revoke/rotate the public link, toggle PDF download, view documents, queue deliveries, settings. |
| Technician | `client/apps/technician_app` | See assigned/walk-in jobs, open the pinned checklist, record assessments/measurements/issues/evidence, view summary/review, sign and complete, sync offline work, profile. |
| Public viewer (no account) | server-rendered `/r/{token}` | View an active inspection report in EN/AR, optional PDF. |
| Designer / developer | `client/apps/ui_gallery` | Design-system showcase only; no routes and no product data (`inferred` from `lib/support` only). |

There is **no customer app/portal** in this repo. README's "customer app/portal" is listed as not implemented. The
public report is the customer-facing surface.

## 3. Core jobs (ranked)

1. Configure the global truth: categories, items, rules, option sets, document types, languages (Platform Admin).
2. Onboard a workshop and its staff (Platform Admin).
3. Build a workshop template from published master item versions (Workshop Admin).
4. Create a job with customer + vehicle and assign a technician (Workshop Admin).
5. Execute the inspection with evidence and a signature (Technician).
6. Review, approve/reject, and publish a tamper-evident report (Workshop Admin).
7. View/download the public report and deliver its link (Public / Workshop Admin).
8. Audit who changed what (Platform Admin).

## 4. Glossary — confirmed, with drift noted

| Term | Meaning |
|---|---|
| **Master category / item / item version** | Platform-owned checklist taxonomy and versioned content. Only published versions are selectable downstream. |
| **Workshop template / template version** | Workshop-owned selection/order of master item versions. Jobs pin a template version. |
| **Job** | A customer vehicle inspection unit (`platform_jobs`). Has customer, vehicle, template version, technician, lifecycle. |
| **Pinned checklist** | JSON snapshot of the template's categories/items/rules stored when the technician first opens the checklist (`platform_job_checklists`). |
| **Assessment** | Technician's result for one item (result code, score, measurements, issue values, note). |
| **Result codes** | `NO_ISSUE_OBSERVED`, `ATTENTION_RECOMMENDED`, `DEFECT_FOUND` (plus `NOT_APPLICABLE`/`COULD_NOT_VERIFY` in legacy paths). |
| **Evidence** | Photo/video/document captured for an item, uploaded, hashed and completed. |
| **Complete / finalize** | Technician submits the inspection. Clean API calls it `complete`; legacy API and many UI strings say `finalize`. **DRIFT.** |
| **Review / approve / reject** | Workshop Admin decision. Approve computes score/grade and creates report version 1. |
| **Publish** | Create/activate the public share link. Requires approval + consent + checklist readiness. |
| **Public link / token** | Anonymous URL credential, stored hashed; rotate/revoke supported. |
| **Report version** | Immutable snapshot of the approved inspection used by the HTML/PDF report. |
| **Delivery** | WhatsApp/SMS/email delivery attempt for a report link (fake provider by default). |
| **Workshop Admin app** | `workshop_admin_app`; README still calls it `admin_app`. **DRIFT.** |
| **Transmission / gearbox** | The job/API field is `transmission`; public report labels it `gearbox`. **DRIFT.** |

## 6. Key entities and relations

`workshop` 1—n `workshop_membership` n—1 `user` (role PLATFORM_ADMIN / WORKSHOP_ADMIN / TECHNICIAN).
`platform_category` 1—n `platform_item` 1—n `platform_item_version` (published/immutable).
`platform_template` 1—n `platform_template_version` 1—n template items → master item versions.
`platform_job` n—1 workshop, n—1 template version, n—1 assigned technician; 1—1 pinned checklist;
1—n assessments; 1—n evidence; 1—n status history; 1—n report versions; 1—n public links; 1—n deliveries.
`report_version` is built from the completed inspection snapshot and drives the public HTML/PDF.

## 7. Lifecycles — confirmed

Job (`InspectionJob`, `WorkshopJobAdminService`): `DRAFT → SCHEDULED → ASSIGNED → IN_PROGRESS → PENDING_REVIEW →
APPROVED → PUBLISHED`; parallel terminal `CANCELLED`; review can set `REJECTED`. Publication states
`UNPUBLISHED / PUBLISHED`; review states `NOT_SUBMITTED / PENDING / APPROVED / REJECTED`.

Evidence: `PENDING → UPLOADED → VERIFIED` (or `DELETED`).

Report: `QUEUED → GENERATING → READY / FAILED`; public link `ACTIVE → REVOKED`; PDF toggle on/off.

Language: `DRAFT → TRANSLATING → REVIEW → LIVE` (migration `V108`), with default language `en`.

Config release (governance): draft → submitted → approved → published → deprecated.

## 8. Integrations

- JWT access/refresh (rotating refresh tokens); optional TOTP; Argon2 password hashing.
- MySQL 8.4 + Flyway; UUIDv7 as `BINARY(16)` in legacy tables and `VARCHAR(36)` in clean tables.
- Local filesystem object storage by default; optional S3 adapter (unused/disabled).
- SMTP mail; fake WhatsApp/SMS delivery provider by default; webhook with HMAC.
- Headless Chromium for PDF (`CHROME_PATH`), Thymeleaf public report.
- Dynamic UI messages: JSON catalogs synced into the DB and served via `/api/v1/i18n/ui-messages/*`.
- Metrics: Actuator/Prometheus.
